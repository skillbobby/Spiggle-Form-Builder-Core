Architecture

How Form Builder is put together

Three layers share one JSON schema: the Filament builder, the public Livewire renderer, and the submission engine.

Headless split

Definition

Form.schema JSON plus metadata columns. Form::document() emits the portable object (schema_version, form_id, name, base_path, container_type, schema).

Renderer

Blade + Livewire PublicForm with a 12-column grid that stacks on mobile. Independent of Filament CSS. FormRenderer::toFilament() maps the same schema to Wizard/Tabs/Section for admin preview.

Submission engine

SubmissionManager sanitizes, stores JSON, optional files. Admin filtering/export lives on FormSubmissionResource.

Forms and submissions use soft deletes.

Portable schema document

{
  "schema_version": "1.0",
  "form_id": "uuid",
  "name": "Contact Us",
  "base_path": "contact-us",
  "container_type": "wizard",
  "schema": [
    { "label": "Details", "fields": [ ] }
  ]
}

SchemaNormalizer assigns container/field UUIDs, unique snake_case names, clamps column span to 1–12, and normalizes options (label, value, color, sort_order). Duplicate field names get a numeric suffix.

Each field may include: type, label, label_position, label_override, required, placeholder, hint, column_span, validation_rules, options, meta.

Public vs Filament rendering

The public page is Livewire with CSRF. Layouts:

TypePublic behavior
singleOne section; one submit. Builder locks to a single section.
wizardProgress bar; nextStep validates only the current container.
tabsClient-side tabs; full validation on submit.
pagesSame step gates as wizard; button says “Save and continue”; session draft between pages.

Drafts live in session key form_builder_drafts.{form_uuid}. Temporary uploads are not stored in the draft. Disable with drafts.enabled = false.

Mobile: field columnSpan(['default' => 12, 'md' => $span]) in Filament; public CSS uses a 12-column grid that stacks below 768px.

Capture path

  1. Visitor submits; Livewire validates via ValidationBuilder (required/nullable + type defaults + extra rule tags + optional validation_hooks callable).
  2. SubmissionManager::capture walks schema fields, stores files to {directory}/{form_id} on the configured disk, sanitizes other values.
  3. Row created with status new, optional IP / hashed IP, user agent, user_id if logged in, meta (e.g. source: public).
  4. FormSubmitted is dispatched. Success message shows; optional redirect URL is linked as “Continue”.

File metadata stored in JSON: disk, path, original name, size, mime, url. This is not Spatie Media on the submission model (keeps a Media trait off the package).

Security

  • Public POST goes through Livewire (CSRF).
  • Text values: strip_tags.
  • Rich text (meta.use_editor) with sanitize_html on: whitelist <p><br><strong><em><ul><ol><li><a><h1><h2><h3><blockquote>.
  • IP storage optional / hashable.
  • Unpublished or inactive forms 404 on the public route.
Public rich editor The admin Filament preview can render RichEditor. The guest Blade template always uses a plain <textarea>. HTML from guests is still sanitized if they somehow post markup.

Exports, queues, audit

  • CSV — native fputcsv.
  • XLSX — SpreadsheetML XML that Excel opens; no PhpSpreadsheet dependency.
  • PDF — minimal Helvetica text; non-ASCII becomes ?. Fine for ops, not a branded report.
  • ExportSubmissionsJob implements ShouldQueue. Filament actions use dispatchSync so a missing worker still works. Files land on the exports disk (default local under form-builder-exports/).

form_builder_audit_logs records exports and bulk status/archive/delete. If activity() exists (Spatie activitylog), that is called too.

Events: FormCreated, FormUpdated, FormDeleted, FormSubmitted, SubmissionsExported.

Composition with Dynamic Fields

  • FieldCatalog delegates to Spiggle\DynamicFields\Support\FieldTypes when that class exists.
  • Form::importCustomFields() copies name, type, label, required, rules, placeholder, hint, options (including color), and meta into the last schema section.
  • Hard-requiring Dynamic Fields was avoided (Composer suggest only).

v1 does not implement optional NoSQL for high-volume entries — MySQL/SQLite JSON column plus indexes on form_id, status, created_at.
